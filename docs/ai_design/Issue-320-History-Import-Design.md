# 历史记录导入

本PR基于 `codex/history-export`，目标分支也是该分支。复用格式版本1的 `syncclipboard-history` 备份：纯文本JSON，或带 `history.json` 及传输附件的ZIP。不修改现有导出格式。

## 入口与交互

Avalonia和WinUI3的历史记录设置页增加“导入历史记录”。选择备份后打开独立模态窗口，读取清单并显示总记录数量，点击“开始导入”后逐条校验并保存。读取/导入期间只显示状态、进度和取消；结束后显示新增、修复、跳过和失败结果，零值的附加项省略。失败报告显示带标题路径，只提供打开文件夹按钮。

取消保留已提交记录，当前尚未提交记录清理本次创建的附件。备份本身始终只读。多个导入窗口互斥。

## 重复记录

按类型及大小写不敏感的哈希识别。用户已确认：恢复缺失附件，保留本机属性。完整记录跳过；缺失/不完整的本地内容从备份校验恢复，只更新文件路径、传输文件绑定和本地可用状态，不修改时间、文本、大小、收藏、置顶、来源、版本及同步状态。已删除的本机记录保留删除状态并跳过，避免恢复附件间接撤销删除。

首次导入保留备份的时间、内容属性及来源，作为本地记录入库。常规历史保留策略继续适用，导入流程本身不为腾出条数而删除其他记录。

## 数据处理

导入专用类型位于 `Core/Utilities/History/HistoryImport/`；通过现有导出文档模型读取备份。文件句柄与ZIP在确认期间保持打开，窗口关闭释放。清单最大64MiB，同时限制实际读取长度。容器/版本错误在入库前拒绝，单条元数据或附件错误记录到报告后继续；附件复制及Group解压前分别核对目标磁盘剩余空间，空间不足或磁盘满立即终止，保留已提交记录并显示原因。

只读取清单引用且路径准确匹配 `files/{ProfileId}/{safeFileName}` 的附件，不整体解压外层ZIP。拒绝文件名路径分隔符、非法本机文件名、重复ZIP条目及不匹配的长度/SHA-256。复用各Profile的语义校验，尤其Group ZIP即使外层SHA匹配也必须匹配Profile哈希。长文本清单预览必须与已校验全文生成的规范预览一致。导入时按Profile重新计算内容大小并核对备份声明；Group解压按记录声明大小进行预检和流式累计限制，不只依赖ZIP标称长度。当前应用不支持的类型报告失败，不凭空创建不可使用的记录。

每条Group最多恢复1,000,000个文件和目录，包含隐式父目录，共享父目录只计一次。解压前检查数量，超过上限跳过该条并写入报告，继续其他记录。此限制仅用于历史导入，不改变普通同步的传输准备逻辑。配置文件 `SyncClipboard.json` 的 `HistoryImport.MaxGroupEntryCount` 可调整，不新增UI；每次开始导入时读取配置值，0表示不允许含文件或目录的Group导入。附件没有固定GB上限，仍受目标磁盘剩余空间和实际字节校验约束；64MiB上限只针对清单。

配置由导入目录内独立的 `HistoryImportConfig` 定义。配置示例（添加或修改HistoryImport节，保留其他配置）：

```json
{
  "HistoryImport": {
    "MaxGroupEntryCount": 1000000
  }
}
```

每条附件放到该Profile工作目录内唯一的 `import-{GUID}` 子目录，绝不覆盖已有路径。校验及Profile持久化完成后，在HistoryManager数据库信号量内再次判断重复/修复需求，再保存。数据库失败或并发重复时仅清理本次子目录；成功入库保留附件。修复旧记录时沿用原哈希对应目录，保证正常删除和保留策略能清理修复附件。通过独立HistoryImported通知界面，避免触发普通新增/更新的同步订阅，不触碰系统剪贴板，不在导入时主动触发上传；用户已确认导入记录仍参与重启、刷新等后续正常历史同步。

未导入记录报告写到备份所在目录，唯一文件名防覆盖。保存报告失败时在结果界面保留原因明细，不把已导入内容误报失败。

## 验证

覆盖短/长文本、文件、图片及文件组导出导入往返，元数据与本地路径恢复、已有记录缺失附件修复和属性保留、重复与删除记录、取消、损坏/缺失/重复附件、路径逃逸、Group语义校验、数据库失败清理与事件失败不删除已提交附件。Avalonia无头测试覆盖阶段显示及取消期间防关闭；WinUI构建由Windows CI验证。
